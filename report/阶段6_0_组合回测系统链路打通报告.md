# 阶段6.0 组合回测系统链路打通报告

> 分支：`feat/dl-plan-stage2`  
> 时间：2026-04-09  
> 定位：阶段6的独立首版，只解决“信号如何进入组合回测框架”，暂不追求实盘级精细撮合。

---

## 1. 这次为什么先做阶段6.0

当前阶段5还不完善，现有几个模型的预测胜率与稳定性都偏弱。

因此，本轮阶段6不应该直接追求“把收益做漂亮”，而应该优先解决：

1. 如何把阶段4/4.1/5/5.2的模型分数统一接入回测系统。
2. 如何把“模型分数”转成“组合净值、回撤、Sharpe、换手率、分层收益”等可比较结果。
3. 如何先打通“阶段5 -> 阶段6”的研究链路，给后续阶段5模型升级留出稳定的回测接口。

所以本次落地的是 **阶段6.0：链路打通版**，而不是最终完整版阶段6。

---

## 2. 阶段6.0的设计目标

阶段6.0的核心目标不是证明模型已经足够强，而是建立一套 **通用、独立、可复用** 的组合回测框架。

本版目标：

- 能接收任意模型输出的横截面分数文件。
- 能按统一规则选股、调仓、扣成本。
- 能输出组合净值、基准净值、风险指标。
- 能输出分层组合曲线。
- 能并行比较不同信号源。

本版不追求：

- 实盘级 T+1 开盘精细撮合
- 停牌/涨跌停/成交额约束的完整建模
- 行业中性化、风格中性化
- 仓位优化、风险预算、动态持仓控制

## 4. 阶段6.0的方法口径

### 4.1 当前收益口径

本版默认使用：

- `label_fwd_ret_5d` 作为个股未来 5 日收益
- `label_bench_ret_5d` 作为同日横截面平均基准收益

这意味着：

- 阶段6.0当前本质上是一个 **研究级 5 日持有回测框架**；
- 它优先解决“信号排序能否变成组合收益”这个问题；
- 还不是最终精细交易执行版回测。

### 4.2 当前调仓规则

首版固定规则为：

- 信号频率：日频横截面分数
- 调仓频率：每 5 个交易日一次（与 5 日标签对齐）
- 选股方式：取前 20% 高分股票
- 持仓方式：等权
- 候选范围：当期 `is_trading = 1` 的股票

### 4.3 当前成本模型

采用简化成本模型：

- 买入侧成本率：`0.0008`
- 卖出侧成本率：`0.0018`

并根据相邻两期权重变化近似计算：

- `buy_turnover`
- `sell_turnover`
- `cost_drag`

这属于研究级简化版，目的是先把成本前/后净值链路建立起来。

## 5. 代码使用方法

脚本开头已写简易说明，典型运行方式如下：

```bash
python portfolio_backtest.py \
  --signal-config data/dl/dl_v52_result.csv::pred_v52::stage5_2_selector \
  --signal-config data/baseline/baseline_v41_result.csv::pred_tree::stage4_1_tree \
  --signal-config data/baseline/baseline_v41_result.csv::pred_blend::stage4_1_blend \
  --features-file data/features/features_v1.parquet \
  --split test \
  --rebalance-every 5 \
  --top-quantile 0.2 \
  --out-dir data/backtest/stage6_0
```

### 参数说明

- `--signal-config`：信号配置，格式为 `路径::分数字段::别名`
- `--features-file`：阶段3特征表
- `--split`：`train / val / test / all`
- `--rebalance-every`：调仓间隔，推荐与标签 horizon 对齐
- `--top-n`：每期选前 N 只股票
- `--top-quantile`：每期选前 q 分位股票
- `--buy-cost-rate` / `--sell-cost-rate`：简化成本参数
- `--out-dir`：输出目录

1. 当前使用的是阶段3标签收益口径，不是最终精细执行收益。

- 阶段5.2、阶段4.1 tree、阶段4.1 blend 已能在统一框架下横向比较；
- 阶段6不再依赖某一个模型单独定制；
- 后续模型升级后，可以直接复用这套框架做同口径评估。

## 8. 为什么说这次实现是“较为独立”的

本次实现刻意保持了独立性：

### 8.1 不改主线 `trainer_app.py`

没有把阶段6.0硬塞进当前页面接口逻辑，避免影响主线看盘/训练功能。

### 8.2 不绑定某一个模型脚本

脚本不依赖某一个特定模型，只要求输入信号文件里有：

- `date`
- `stock_code`
- 指定分数字段

所以后续阶段5换模型时，阶段6.0不需要重写。

### 8.3 与旧 `backtest/` 包并存

当前已有的 `backtest/` 目录更偏传统单标的 signal 回测；
本次 `portfolio_backtest.py` 则是阶段6需要的 **横截面选股组合回测**。

两者暂时并行存在，避免互相污染。

## 9. 当前版本的边界与不足

阶段6.0已经能用，但边界必须讲清楚：

### 9.1 仍不是实盘级撮合

当前没有精细实现：

- T 日收盘信号、T+1 开盘成交的严格撮合
- 停牌约束
- 涨跌停无法成交约束
- 成交额/流动性约束
- 单票成交冲击

### 9.2 当前收益口径仍依赖阶段3标签

这让阶段6.0非常适合做研究闭环，但仍属于“研究回测”，不是最终执行回测。

### 9.3 当前权重规则较简单

目前仅支持：

- 等权
- TopN / TopQuantile
- 固定调仓频率

还未扩展到：

- 市值权重
- 分数权重
- 风险平价
- 行业/风格约束

## 10. 对阶段6后续版本的建议

### 阶段6.1
重点升级交易现实性：

- 切换到更严格的 T+1 执行口径
- 处理停牌 / 涨跌停 / 不可成交
- 引入更细的成本与换手分析
- 输出更完整的调仓日志

### 阶段6.2
重点升级策略层：

- TopN vs TopQuantile 比较
- 周调仓 vs 5日调仓比较
- 等权 vs 分数权重比较
- 多模型组合 vs 单模型比较

### 阶段6.3（或阶段7衔接）
重点升级稳健性：

- 不同市场阶段切片
- 不同股票池切片
- 不同成本假设压力测试
- 不同调仓频率稳健性测试

---

## 11. 总结

本次阶段6.0已经完成的，不是“把阶段6全部做完”，而是更关键的一步：

**把“阶段5模型分数”稳定地接入了一个独立的横截面组合回测框架。**

这意味着：

1. 阶段5到阶段6的链路已经打通。
2. 阶段6现在可以作为统一评估框架存在。
3. 后续阶段5模型升级时，不需要重新造一套回测系统。
4. 当前阶段6总体仍未完成，但阶段6.0已经为后续 6.1 / 6.2 打好了底。

一句话概括：

**先不要纠结阶段5现在强不强，阶段6.0的价值在于，已经把“弱信号也能进入统一组合回测”这条研究链路打通了。**
